Taking the project-code record (each cell's status record, and the one `resume=True` and `cache_dir=` compare) no longer imports a module loaded through `importlib.util.LazyLoader` (as `lazy_loader.load` does). In a notebook it imported each such module a notebook name held, even one the task does not use, and in a script one the task imports or a `functools.partial` binds; an error from that import was hidden, and the module was left half loaded, so the user's next read of it raised an `AttributeError` instead of the error. The record now reads these modules without running them and records the same files. Provenance no longer imports a lazily loaded `torch` that the task did not use. Hydra's launch can still import such a module, so one that fails to import can now make a notebook's `run()` raise its error, as a script's already could: import such a module yourself before `run()`.
