`resume=True` and `cache_dir=` now notice edits to code defined in a notebook. A task defined in a notebook cell is compared by what its code looks up in the kernel when the run starts: each helper and class defined in a cell, by its definition and the defaults and class attributes it captured, and each plain constant (a number, a string, a tuple of them) by its value. Re-running an edited cell and resuming re-runs the cells, with a warning naming it (`helper (notebook)`), and the cache recomputes them; re-running an unchanged cell, extending the grid or a restart that replays the cells does not. A mutable value (a dict config, a list), an object's state, a name the task rebinds, a value named like a secret, and code whose text the kernel does not keep (a `%%time` cell, `exec`, a `%run` file) are not compared. A value that differs per session, such as a timestamp or a seed drawn in a cell, re-runs the cells after a restart.
