`resume=True` and `cache_dir=` now notice edits to code defined in a notebook. A task defined in a notebook cell is compared by the definitions its code reaches by name in the kernel when the run starts: each function and class defined in a cell (through decorators, a `partial`, a bound method or an instance). Re-running an edited cell and resuming re-runs the cells, with a warning naming it (`helper (notebook)`), and the cache recomputes them; re-running an unchanged cell, extending the grid or a restart that replays the cells does not. No value is compared (a number, a string, a dict config, what a default or a closure holds): a value is only safe to compare when every writer of it is known, which a notebook does not allow, so pass values the results depend on as swept parameters, or use a new `working_dir` after editing one. A function reached only through a container (a registry), a closure or a default, a name one of the notebook's functions rebinds (`global helper`), a `_target_` defined in the notebook, and code whose text the kernel does not keep (a `%%time` cell, `exec`, a `%run` file) are not compared either. A name rebound through `globals()` or `exec`, or by a function the notebook's names do not lead to (one kept only in an object's attributes), is still compared, so once a run rebinds it in the kernel, a resume re-runs the cells; the resilience guide lists where mushin looks. A cell's `import pkg.sub` binds only `pkg`, so `pkg/sub.py` is compared only if something else brings it in: write `from pkg import sub` (or `import pkg.sub as sub`) instead.
