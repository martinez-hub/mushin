`resume=True` and `cache_dir=` now notice edits to code defined in a notebook. A task defined in a notebook cell is compared by what its code looks up in the kernel when the run starts: each helper and class defined in a cell, by its definition and the defaults and class attributes it captured, and each number (or tuple of numbers) by its value. Re-running an edited cell and resuming re-runs the cells, with a warning naming it (`helper (notebook)`), and the cache recomputes them; re-running an unchanged cell, extending the grid or a restart that replays the cells does not. A string constant is compared only through the code that reads it, never by value, since a digest of one could confirm a guess of a secret: after editing one, such as a model name, use a new `working_dir` or make it a swept parameter. A mutable value (a dict config, a list), an object's state, a name or closure variable the task rebinds, a `_target_` defined in the notebook, and code whose text the kernel does not keep (a `%%time` cell, `exec`, a `%run` file) are not compared. A value that differs per session, such as a timestamp or a seed drawn in a cell, and state the task changes through `setattr`, `globals()` or `exec` re-run the cells on the next resume.
