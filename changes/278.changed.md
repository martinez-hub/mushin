`resume=True` and `cache_dir=` now notice edits to code defined in a notebook. A task defined in a notebook cell is compared by the definitions its code reaches by name in the kernel when the run starts: each function and class defined in a cell (through decorators, a `partial`, a bound method or an instance). Re-running an edited cell and resuming re-runs the cells, with a warning naming it (`helper (notebook)`), and the cache recomputes them; re-running an unchanged cell, extending the grid or a restart that replays the cells does not. No value is compared (a number, a string, a dict config, what a default or a closure holds): a value is only safe to compare when every writer of it is known, which a notebook does not allow, so pass values the results depend on as swept parameters, or use a new `working_dir` after editing one. A function reached only through a container (a registry), a closure or a default, a `_target_` defined in the notebook, and code whose text the kernel does not keep (a `%%time` cell, `exec`, a `%run` file) are not compared either.
