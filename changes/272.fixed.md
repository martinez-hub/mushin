mushin's own console output no longer fails with `UnicodeEncodeError` on a console that cannot encode what it prints (a Windows pipe in cp1252, a cp437 console, `PYTHONIOENCODING=ascii`). `show`, `diff` and the `dry_run=True` preview print a metric name or other value outside the console's encoding as a backslash escape such as `\u03b1`, with the table's columns still aligned, while the returned `.table` keeps the text itself. `python -m mushin guide --path` prints only a real path: one the console's encoding cannot represent goes out as the path's own bytes when stdout's encoding is the file system's, and otherwise (a Windows pipe in cp1252, for one) the command fails with a message saying how to widen stdout. The text files mushin writes are UTF-8 on every platform, and mushin reads them as UTF-8. This changes `export.table(root, path=...)`: its CSV was written in the locale's encoding (on Windows, cp1252, which failed on a metric name outside it) and is now UTF-8 without a byte-order mark, which pandas and polars read as is; Excel on Windows needs Data > From Text/CSV (or the import wizard) to read it as UTF-8. `capture_env=True` decodes uv's output as UTF-8 (in the locale's encoding, a non-ASCII path in it came out garbled, or the snapshot silently fell back to the bare package list), and with `on_error="nan"` a cell whose error message the locale's encoding lacked no longer ends the sweep, since `mushin_error.txt` is UTF-8; the MCP server's `get_failures` reads it as UTF-8, falling back to the locale's encoding for a file an earlier release wrote. The default `metric_load_fn` reads a JSON metrics file as UTF-8 (or UTF-16 or UTF-32) and falls back to the locale's encoding, so a UTF-8 file no longer reads garbled on Windows. Provenance records a non-ASCII git branch name as UTF-8. mushin's own console text, warnings and error messages are now plain ASCII, so the `diff` table heads its delta columns `<metric>(b-a)` instead of `Δ<metric>` (one token per column still; code that parses `DiffResult.table` must look for the new header, and `DiffResult.rows` is unchanged) and the dry-run preview opens with `Dry run: N cells`. `target_job_dirs` naming a file now says the path is not a directory rather than that it does not exist.
