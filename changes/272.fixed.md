mushin's own console output no longer fails with `UnicodeEncodeError` on a console that cannot encode what it prints (a Windows pipe in cp1252, a cp437 console, `PYTHONIOENCODING=ascii`). `show`, `diff` and the `dry_run=True` preview print a metric name or other value outside the console's encoding as a backslash escape such as `\u03b1`, with the table's columns still aligned, while the returned `.table` keeps the text itself. `python -m mushin guide --path` prints a path the console cannot encode as the path's own bytes, or fails with a message when stdout takes no bytes, so its output is always a usable path. With `on_error="nan"`, a cell whose error message the locale's encoding lacks no longer ends the sweep: `mushin_error.txt` is now written in UTF-8. mushin's own console text, warnings and error messages are now plain ASCII, so the `diff` table heads its delta columns `<metric> (b-a)` instead of `Δ<metric>` (code that parses `DiffResult.table` must look for the new header; `DiffResult.rows` is unchanged) and the dry-run preview opens with `Dry run: N cells`. `target_job_dirs` naming a file now says the path is not a directory rather than that it does not exist.
