mushin's own console output no longer fails with `UnicodeEncodeError` on a console that cannot encode what it prints (a Windows pipe in cp1252, a cp437 console, `PYTHONIOENCODING=ascii`). `show`, `diff` and the `dry_run=True` preview print a metric name or other value outside the console's encoding as a backslash escape such as `\u03b1`, with the table's columns still aligned, while the returned `.table` keeps the text itself. `python -m mushin guide --path` prints only a real path: one the console's encoding cannot represent goes out as the path's own bytes when stdout's encoding is the file system's, and otherwise (a Windows pipe in cp1252, for one) the command fails with a message pointing at `PYTHONUTF8=1`. The text files mushin writes are UTF-8 on every platform, and mushin reads them as UTF-8. This changes `export.table(root, path=...)`: its CSV was written in the locale's encoding (on Windows, cp1252, which failed on a metric name outside it) and is now UTF-8. It also fixes `mushin_env.txt` (`capture_env=True` wrote no snapshot at all when the write failed) and `mushin_error.txt` (with `on_error="nan"`, a cell whose error message the locale's encoding lacked ended the sweep), and the MCP server's `get_failures` reads those tracebacks as UTF-8. mushin's own console text, warnings and error messages are now plain ASCII, so the `diff` table heads its delta columns `<metric> (b-a)` instead of `Δ<metric>` (code that parses `DiffResult.table` must look for the new header; `DiffResult.rows` is unchanged) and the dry-run preview opens with `Dry run: N cells`. `target_job_dirs` naming a file now says the path is not a directory rather than that it does not exist.
