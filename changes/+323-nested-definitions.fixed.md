A driver script's code record now reads a function defined with `def` in a top-level `if`, `try`, `with`, loop or `match` block as it reads a top-level one: its parameters, its locals and a generic function's own type parameters (and a `type` statement's) no longer count as reads of the script's names. Before, a grid named like such a function's parameter (`lr = [0.1, 0.01]` beside `if HAS_GPU: def helper(lr): ...`) made extending it an edit on `resume=True` or `cache_dir=`. A class in such a block, and a function there that holds a class, is still read whole, since a class body can read a script name it binds; a lambda's parameters and a comprehension's variables in a block still count. A script whose record counted a statement only through such a name recomputes once after upgrading.
