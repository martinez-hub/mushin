A swept string that would not reach the task as written is now refused before launch, a dry run included, with a `ValueError` naming each such value and how it would arrive. `multirun` sweeps through Hydra's `choice()`, which writes each job's value without its quotes. So `multirun(["true", "false"])` reached the task as `True` and `False` (its cells NaN in the dataset), `"null"` as `None`, and `"1"`, `"1.5"` or `"1e3"` as a number. A string Hydra cannot write unquoted, such as `"it's"`, one holding `#` or `~`, or a non-ASCII one, failed inside the launch. The check covers any value written as a string, such as a NumPy string, a `Path` or a `Decimal`. A field the composed config types `str` (a defaults-list group's config included) turns some values back (`"1"` arrives as `"1"`), and those still run; `to_dictconfig=True` drops those types. A config group's option named like a number would fail in its job and is refused too. A job directory `target_job_dirs=` cannot write is refused with its own message. A sweep under a sweeper other than Hydra's basic one is not checked. Every sweep the check does not refuse runs exactly as before, each job's override unchanged.

Migration: a sweep such as `multirun(["1", "2"])` into an untyped key, which handed the task ints, now raises. Pass the values as the type the task used (`multirun([1, 2])`), or sweep the strings through a raw comma sweep, whose values keep their quotes, in place of the `multirun` argument. The error names that override, such as `overrides=["+c='1','2'"]`. A one-value sweep has no such form: pass the value fixed (`c="1"`).
