A swept string that Hydra would not hand the task as written is now refused before launch, a dry run included, with a `ValueError` naming each such value and how it would arrive. `multirun` sweeps through Hydra's `choice()`, which writes each job's value without its quotes. So `multirun(["true", "false"])` reached the task as `True` and `False` (its cells NaN in the dataset), `"null"` as `None`, and `"1"`, `"1.5"` or `"1e3"` as a number. A string Hydra cannot write unquoted, such as `"it's"`, one holding `#` or `~`, or a non-ASCII one, failed inside the launch. The check covers any value written as a string, such as a NumPy string, a `Path` or a `Decimal`, and the job directories `target_job_dirs=` sweeps. Every sweep it does not refuse runs exactly as before, each job's override unchanged.

Migration: a sweep such as `multirun(["1", "2"])`, which handed the task ints, now raises. Pass the values as the type the task used (`multirun([1, 2])`), pass a single string as a fixed value (`c="1"`), or sweep the strings through a raw override, whose values keep their quotes, in place of the `multirun` argument. The error names that override, such as `overrides=["+c='1','2'"]`.
