On Python 3.14 and later, a task whose annotations name an import made only for type checking now runs. That covers `if TYPE_CHECKING: from decimal import Decimal` then `def task(a: int, h: Decimal = None)`, and a submodule imported that way (`h: pkg.sub.T`). Before, `.run()` raised `NameError` or `AttributeError`, because mushin, and hydra-zen's `zen` through it, read the task's signature by evaluating its annotations. When evaluating them fails, mushin now reads the signature with each annotation kept as its text. That applies to the task, `pre_task`, `validate()`, and a metric passed to `compare_llms`. As a result, a misspelled name in such an annotation is no longer caught at `.run()`; Python 3.14 already stopped catching it at the definition. A name the task's body also uses still fails, in the cell that runs it. hydra-zen's own `builds(task, populate_full_signature=True)` in your code still evaluates the annotations. `validate()` now also leaves out a task's `mushin_resume` parameter, as `.run()` does.
