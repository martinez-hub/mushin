A driver script's code record now counts the names in a string that a type-hint reader resolves outside an annotation: in a type alias an annotation names (`Alias = list["T"]` with `def task(x: Alias)`, through other aliases too), in one declared `Alias: TypeAlias = "T"`, in a functional `NamedTuple`'s, `TypedDict`'s or `make_dataclass`'s field types, in a `TypeVar`'s bound or constraints, and in `ForwardRef("T")`. Editing such a name (`T = int` to `T = str`) reused the completed cells on `resume=True` or `cache_dir=`, though `typing.get_type_hints` and pydantic see the new value. A string argument of any other call in an annotation (`NewType("grid", int)`) is now a value and names nothing, as a `Literal` value does, so it no longer makes extending a grid named like it an edit. A script whose counted code has such a string recomputes once after upgrading.
