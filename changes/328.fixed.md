A driver script's code record now counts the names its annotations read as text. Under `from __future__ import annotations`, or with an annotation written as a string (`x: "Config"`), a module-level name that only a method's, a nested function's or a class body's annotation named was not compared. Editing it (`T = int` to `T = str`, or the import a type comes from) then reused the completed cells on `resume=True` or `cache_dir=`, though whatever reads the type hints (hydra-zen's `builds(..., populate_full_signature=True)`, a dataclass config's field types) sees the new value. A script whose counted code has such an annotation recomputes once after upgrading. On Python 3.14+, `@mushin.sweep` also no longer evaluates the task's annotations when it is applied, so an annotation can name a class defined below the task, as plain Python allows (#326).
