`max_total_seconds` now holds under a parallel launcher. Under `launcher="joblib"` every job unpickled the task runner with no deadline of its own, so the budget never fired and every cell ran. Now the sweep's first computed cell, in whichever worker runs it, records the start in a hidden file in the sweep directory (`.mushin_budget_start.<id>`), each worker process keeps the deadline it derives from it, and no worker starts a cell once `max_total_seconds` have passed since then: the budget bounds the sweep's elapsed time, not the compute summed over the workers, and each worker can finish a cell it started just before the deadline. `run` removes the file when its launch returns normally; a launch that raises (a failed cell under `on_error="raise"`, Ctrl-C, a submitit timeout) leaves it, so jobs a scheduler still holds keep the same deadline. Each `run()` names its own start file, so no later run reads it, and a `resume=True` that passes `max_total_seconds` again starts a new clock. A cell that SLURM preempts and requeues after the deadline still runs, since it started before it. The default sequential launcher keeps the deadline in memory, as before, and writes no file. Across nodes (submitit), the workers need the shared filesystem submitit already requires and synchronized clocks; a cell that runs on several ranks still disables the budget.
