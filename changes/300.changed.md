In an IPython shell, mushin's cell watch now walks the live classes once per cell instead of twice: a cell starts from the classes the previous cell ended with, unless another execution ended since or the cell runs inside one. With torch, Lightning, numpy, pandas and xarray loaded, that cuts the watch's cost from about 16 to 20 ms to about 8 ms per cell on an Apple M1. A frontend that runs a silent execution between cells (a variable inspector) keeps the old cost. A class that code outside any cell makes between two cells (a background thread, a callback, an expression a frontend evaluates after a cell) may now be taken for one the next cell made, as one made while a cell runs already could.
