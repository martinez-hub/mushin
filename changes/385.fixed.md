A cell's record now holds the swept values its task ran with: they are read again after `pre_task` and after the task, once zen's wrapper has resolved the config. A resolver that gives a new value on each call (a counter, say) left the record naming a value read before that resolution, which the task never got. mushin adds no resolution of its own, so an escaped interpolation and a task run without zen's wrapper behave as before.
