A `hydra_list` value now reaches the task as written: a backslash is no longer doubled (`hydra_list(["a\\b"])` arrived as `['a\\\\b']`), and `None` arrives as `None`, not the string `'None'`. A dict key that Hydra's override grammar cannot write as itself (a string key that reads as another type, such as `"1"` reaching the task as `1`, or one holding `=` or `:`) is now refused before launch with a `ValueError` naming it. Hydra has no quoted dict keys, so put such a dict in the workflow's `eval_task_cfg` instead. `HydraDDP` now quotes a re-launched rank's run directory as a swept string is quoted, so a path holding a quote parses; a path holding `${` is still read as an interpolation. Not changed: in a string holding `${`, a backslash that is neither right before the `${` nor inside the interpolation may still arrive doubled; write such a path with `/`, or put the value in the config.
