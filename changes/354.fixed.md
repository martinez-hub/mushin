On `launcher="submitit_slurm"` or `"submitit_local"`, a job that ends without returning after its cell has completed (its result reached the driver too late, or, in a job of several tasks, another task died after the first one returned) can now keep the cell's result rather than become a failed cell. A cell's `mushin_cell_status.json` now records the run that wrote it, the job and which of the job's tasks (`run_id`, `job_id`, `task`); mushin keeps a completed record only when this run's first task wrote it for that cell. A job that dies before its cell starts now also replaces an earlier run's failed or skipped record of the same cell, so the cell's `mushin_error.txt` is this job's. A cell that starts computing removes a `mushin_metrics.json` an earlier sweep left in its directory, which a cell whose task returns None used to leave to be read back as its result.
