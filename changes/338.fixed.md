A driver script's code record now counts a script name that a class body reads before binding it, since Python reads the script's value until a binding in the class body runs. This covers `lr = lr`, `lr += [3]`, `for lr in lr:`, a read before `lr = ...`, a read after a binding inside an `if`, and a method's default or a decorator argument before the binding. It also covers any read of a name the class body can unbind (a `del` of it anywhere in the body, or an `except ... as lr` handler, outside that handler) and a comprehension's read of a class name, since a comprehension never sees the class's names. Before, editing such a name (`lr = 0.1` to `lr = 0.2`) reused the completed cells on `resume=True` or `cache_dir=` for a class at the top level, in the main block or in a function. That included a comprehension's read on Python 3.12 and later, which inlines comprehensions, and `+=` in a class anywhere. A class in a top-level block was already read whole. A read after a binding that runs only in some branches (a `try` that binds the name in each) or after a walrus also counts, as does any read of a name a `del` at the end of the class body removes, which may recompute once too often. A script whose class body reads such a name recomputes once after upgrading.
