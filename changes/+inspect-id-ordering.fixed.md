`examples/inspect_ai_compare.py` now returns question ids in their own order rather than as strings. Inspect numbers samples `1, 2, 3...` by default, and sorting those lexicographically gave `1, 10, 11, ... 2, 20`. The pairing was still correct — every model got the same order — but that list is what a caller lines `clusters=` up against, so a surprising order silently misaligned the groups. Ids with no total order (mixed types) still fall back to string ordering. The adapter is now also tested against real `inspect_ai` `EvalLog` objects rather than only against duck-typed stand-ins, which is what would have caught an upstream field rename.
