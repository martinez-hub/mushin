Each cell's `mushin_provenance.json` records the accelerator (CUDA and cuDNN build, device) from the process that ran the cell, once its task has returned, instead of from the process that called `run()` before the first cell. A task that imports torch inside its body, and a sweep launched from a login node with submitit, now record the device the cell ran on; the device is named once the task has initialized CUDA, and provenance itself makes no CUDA call. A sweep that never imports torch no longer imports it for the record, which saves the torch import (about half a second here) on every `run()`; its `accelerator` is `null` when the cell's process never loaded torch (so a task that uses a GPU through JAX or a subprocess in such a process records `null` too), while a process with torch loaded records torch's view even if the task did not use it, `null` values when it found no device. `mushin.diff` compares the accelerator only when both sweeps recorded one, so a torch sweep against a scikit-learn sweep on the same machine reports no hardware change, while a CPU-only torch build against a GPU box still does.
