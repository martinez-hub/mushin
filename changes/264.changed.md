Each cell's `mushin_provenance.json` records the accelerator (CUDA and cuDNN build, device) from the process that ran the cell, once its task has returned, instead of from the process that called `run()` before the first cell. A task that imports torch inside its body, and a sweep launched from a login node with submitit, now record the device the cell ran on; the device is named once the task has initialized CUDA, and provenance no longer initializes it (which, in a reused worker, made the next cell's `pin_gpu_round_robin` raise). A sweep that never imports torch no longer imports it for the record, which saves the torch import (about half a second here) on every `run()`; its `accelerator` is `null`, where a loaded torch that found no device still records `null` values, and a task that uses a GPU without importing torch (JAX, a subprocess) records `null` too. `mushin.diff` compares the accelerator only when both sweeps recorded one, so a torch sweep against a scikit-learn sweep on the same machine reports no hardware change, while a CPU-only torch build against a GPU box still does.
