`resume=True` and `cache_dir=` now notice edits to the project code a task reaches, not only to the task function itself: the module that defines the task and, transitively, the project modules it imports are fingerprinted from disk when `run()` starts, as code: comments, formatting and a script's `if __name__ == "__main__":` block do not count (installed packages, mushin and the interpreter are left out; a file edited after the process imported it is not fingerprinted, with a warning to restart), a cell completed under different project code re-runs with a warning that names the changed files, and the cache key includes the same fingerprints, so a cell computed before this change by a task defined in a project file is recomputed once. `Study` fingerprints the project code each method reaches the same way. Sweeps recorded without the new field still resume.
