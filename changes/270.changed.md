`resume=True` and `cache_dir=` now notice edits to the project code a cell can run, not only to the task function itself. Each cell records every project file its task's module imports (and `pre_task`'s), directly or through other project files, at any depth (imports inside functions included), and the modules of the classes its config names (`_target_`, or hydra-zen's `just()` and `zen_meta`). Each file is compared as a whole, by its syntax tree without its main block and docstrings, so an edit anywhere in it re-runs the cells and a comment, a docstring or formatting does not; the task function's own source is compared as text, as before, so any edit to it counts. A task defined in the driver script is compared by what its definition can reach by name in the script (its helpers and constants), not by the `run(...)` call, top-level calls, `print` calls or what only they read, so extending a grid and resuming still reuses the completed cells; the script is read when the run starts, so editing it while a sweep runs does not change what its cells record. A cell completed under different project code re-runs with a warning naming the file (`helpers (file)`). Files are compared as they are on disk, so after editing a module in a running process, reload it (or restart) before resuming or using the cache: the old code still runs (mushin warns when it recorded the file earlier in that process). The standard library, installed packages other than editable ones, mushin, and code defined in a notebook are left out. The cache key includes the same record, so a cache entry written by an earlier mushin is recomputed once; a partial task is still never cached, as before, and its bound arguments are not compared (the modules of the functions it binds are). `Study` covers the project files its training functions' modules import the same way, and its methods fingerprint is unchanged. Sweeps recorded without the new field resume without comparing it.
