`resume=True` and `cache_dir=` now notice edits to the project code a cell can run, not only to the task function itself. Each cell records every project file its task's module imports (and `pre_task`'s), directly or through other project files, at any depth (imports inside functions included), and the modules of the classes its config names (`_target_`, or hydra-zen's `just()` and `zen_meta`). Each file is compared as a whole, by its syntax tree without its main block and docstrings, so an edit anywhere in it re-runs the cells and a comment, a docstring or formatting does not. A task defined in the driver script is compared by the script's code without what drives the sweep (its main block, the `run(...)` call, `print` calls and assignments only they read), so extending a grid and resuming still reuses the completed cells. A cell completed under different project code re-runs with a warning naming the file (`helpers (file)`). A file edited after the process imported it, and not reloaded, is recorded as stale, so cells computed with the old code re-run once a process runs the new one. The standard library, installed packages other than editable ones, mushin, and code defined in a notebook are left out. The cache key includes the same record, so a cache entry written by an earlier mushin is recomputed once, and a partial task that binds an argument the key cannot tell apart from another of its type (an array) is not cached. `Study` covers the project files its training functions' modules import the same way, and its methods fingerprint is unchanged. Sweeps recorded without the new field, or under another Python version, resume without comparing it.
