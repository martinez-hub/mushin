`resume=True` and `cache_dir=` now notice edits to the project code a cell reaches, not only to the task function itself. The walk starts from the names the task's code uses (and `pre_task`'s, and the classes the cell's config names as `_target_` once their module is imported) and follows them through the project's own functions, classes, modules and constants as the cell's process has loaded them: a helper it calls, a constant it reads (`from consts import THRESH` included), a class in a registry dict, a function defined in a notebook or a script's main block. Functions are hashed by their bytecode, so a comment is not an edit; the standard library, installed packages other than editable ones, and mushin are left out. A cell completed under different project code re-runs with a warning naming where the change is (`helpers:scale`), and the cache key includes the same fingerprints, so a cell computed before this change by a task that uses project code is recomputed once. `Study` covers the project code its training functions use the same way, and its methods fingerprint is unchanged. Sweeps recorded without the new field, or under another Python version, resume without comparing it.
