`max_total_seconds` now holds under a parallel launcher. Under `launcher="joblib"` every job unpickled the task runner with no deadline of its own, so the budget never fired and every cell ran. Now the sweep's first computed cell, in whichever worker runs it, records the start in a hidden file in the sweep directory (`.mushin_budget_start.<id>`, removed when `run` returns), and no worker starts a cell once `max_total_seconds` have passed since then: the budget bounds the sweep's elapsed time, not the compute summed over the workers. Each `run()` names its own start file, so a `resume=True` with a budget gets a fresh one even after a killed run left its file behind. The default sequential launcher behaves as before. Across nodes (submitit), the workers need the shared filesystem submitit already requires and synchronized clocks; a cell that runs on several ranks still disables the budget.
