In a notebook, `resume=True` and `cache_dir=` now compare a function or class defined in a cell that an annotation of the reached code names: a parameter's, a return's, a class attribute's (a dataclass field's) or a type parameter's, in a string too (`def task(x: Helper)`, `x: "Helper"`, `list["Helper"]`), and what such a definition reaches in turn. Before, editing such a class and resuming reused the completed cells, though `typing.get_type_hints`, pydantic and hydra-zen's `builds(..., populate_full_signature=True)` read it. On Python 3.13 and earlier, an annotation that is not a string holds the class its name meant when its cell ran: after editing such a class, re-run the cell that annotates with it too. A class an annotation reaches only through a type alias (`Opt = Optional[Helper]`) is not compared. A resume keeps the record a reused cell was written with, so a sweep started on 0.18.2 or earlier does not compare such a definition for its completed cells: after editing one, use a new `working_dir`. A notebook task whose record gains such an entry misses `cache_dir` once after upgrading.
