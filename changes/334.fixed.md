A driver script's code record now counts the names in a string that a type-hint reader resolves in a type alias an annotation names, where the alias is written as a type expression: `Alias = list["T"]` or `typing.Optional["T"]` with `def task(x: Alias)`, through other aliases too, one declared `Alias: TypeAlias = "T"` or a `type` statement, and a functional `NamedTuple`'s, `TypedDict`'s or `make_dataclass`'s field types, a `TypeVar`'s bound or constraints, a `NewType`'s supertype and `ForwardRef("T")`. Editing such a name (`T = int` to `T = str`) reused the completed cells on `resume=True` or `cache_dir=`, though `typing.get_type_hints` and pydantic see the new value. The name such a form is given (`NewType("grid", int)`, a field's name, a `TypedDict` key) is a value and names nothing, as a `Literal` value does, so `def task(a: NewType("grid", int))` no longer makes extending a grid named `grid` an edit. A script whose counted code has such a string recomputes once after upgrading.
