A driver script's code record now counts the names in a string that a type-hint reader resolves outside an annotation: in a type alias an annotation names (`Alias = list["T"]` with `def task(x: Alias)`, through other aliases too), in one declared `Alias: TypeAlias = "T"`, in a functional `NamedTuple`'s, `TypedDict`'s or `make_dataclass`'s field types, in a `TypeVar`'s bound or constraints, and in `ForwardRef("T")`. Editing such a name (`T = int` to `T = str`) reused the completed cells on `resume=True` or `cache_dir=`, though `typing.get_type_hints` and pydantic see the new value. The name such a form is given (`NewType("grid", int)`, a field's name, a `TypedDict` key) is a value and names nothing, as a `Literal` value does, so `def task(a: NewType("grid", int))` no longer makes extending a grid named `grid` an edit. A script whose counted code has such a string recomputes once after upgrading.
