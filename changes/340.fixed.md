A `hydra_list` value now reaches the task as written. A backslash is no longer doubled (`hydra_list(["a\\b"])` arrived as `['a\\\\b']`), and `None` arrives as `None`, not the string `'None'`. A nested tuple, dict or `range`, and a NumPy array (as nested lists, in a `multirun` too), now reach the task where they used to fail to parse. A nested `hydra_list`, `multirun` or OmegaConf `ListConfig` still arrives as a list, a `ListConfig`'s interpolation (`${a}`) written unresolved, for the job. An element of another type, such as a set, reaches the task as its text, as a swept value of that type does.

A dict key that would not reach the task as itself is now refused before launch with a `ValueError` naming it. That covers a string key that reads as another type (`"1"` arrived as `1`), one holding `=` or `:` or a leading or trailing space, and a `None` key, which OmegaConf does not take. Hydra has no quoted dict keys, so use a key Hydra writes as itself, or build the dict in the task. A key mixing `str` into an `Enum` is written as its value, and a NumPy NaN key is kept.

`HydraDDP` now quotes a re-launched rank's run directory and job name as Hydra's own writer does. A `"` in the run directory, or `=` or `,` in `job_name=`, used to break every child rank.

Not changed: in a string holding `${`, a backslash that is neither right before the `${` nor inside the interpolation may still arrive doubled; write such a path with `/`, or put the value in the config.
